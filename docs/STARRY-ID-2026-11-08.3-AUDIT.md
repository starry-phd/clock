## 二、此次 2026-11-08.3 的實際差異

### 1. 顯示名稱由 Starry ID 決定

- **Expo、Web** 原先在會員標頭使用 `profile.display_name`，現在改成**直接顯示 `profile.shown_name`**；它為 `null` 時才使用中央 `profile.initials`。不把真名與暱稱自行組合；不在 Clock 自訂「主要顯示名稱」選項，會員到 Starry ID 帳號中心設定。
- 會員姓名原編輯功能仍更新中央 `display_name` 欄位，但新增白話提示：主要顯示名稱以中央選擇為準。Clock 目前沒有排行榜，不新增 `/v1/directory/members` 呼叫；若日後有其他會員清單，官方 OpenAPI 已有 `shown_name`，同樣應直接使用。

### 2. 簽名頭像以「URL 問號前路徑」識別

- `GET /v1/me` 的 `profile.avatar_url` 為一小時有效的簽名網址；Expo 原生與 Web 只接受中央 `id.starry.phd` 的 `/v1/avatars/…` 圖片，可兼容相對路徑與絕對網址；不自建頭像上傳、不保存圖片或 Token 到 Clock DB。
- **快取的邏輯 key 是 `new URL(avatar_url).pathname`**，不以 `user_id`、`member_no` 或每小時變動的 `?sig=` 當圖片 key。Web 已載入圖片且路徑不變時，不會因簽名參數更新而重下載；路徑變更則換圖。React Native Image 以此路徑為 `key` 強制重新掛載新頭像，網路圖片快取仍受原生平台圖片載入器管理，**未新增本機磁碟快取**。
- `avatar_url=null` 或圖片載入失敗時顯示中央 `initials`；Web 只放行中央圖像來源、`no-referrer`。每次 Expo 回到前景、Web 分頁重新可見或打開設定畫面，都再讀 `GET /v1/me`，同步新路徑及 `shown_name`，不輪詢或中斷離線倒數。

### 3. 公開欄位的免費電池加成由中央處理

- 使用者在 Starry ID 網頁帳號中心公開有填內容的欄位，加成由中央計算；Clock **不做欄位清單加成計算、顯示獎勵進度條、倍率相乘或提供序號兌換入口**。舊有月額度和 Quantum 顯示直接使用中央 `balance.allowance/remaining`／`quantum.available`。

### 4. 不變更的範圍

- 既有可修改 `member_no` 仍用於公開頁 `https://id.starry.phd/<member_no>`、分享 `https://id.starry.phd/Invite/<member_no>`，會員所有權仍以 `user_id` 為準。
- Google／Apple 中繼、Passkey、iOS 共用 Keychain 群組 `$(AppIdentifierPrefix)phd.starry.shared`、同瀏覽器 Web SSO 均不重做。
- Android 共用登入依 2026-11-07.14 已為**選做**，不阻擋本次 PR。Android Play SHA-256 由業主回報已登記，EAS Preview／本機 APK 若簽章不同，仍須各自登記。Play 簽章取自 Play Console → 應用程式完整性 → App signing key certificate；EAS 測試 APK 可用 `eas credentials -p android` 或 `apksigner verify --print-certs` 取得對應實際簽章。
- Cloudflare Worker 名稱仍為 `clock-api-staging`／`clock-api`（API）、`clock-staging`／`clock`（Web），沒有建立新資源。
