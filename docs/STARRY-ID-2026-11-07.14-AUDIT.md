## 2026-11-07.14 新增的登入要求

**iPhone 必做：已在 Clock 專案補上，尚待真機驗證。** `apps/clock/app.json` 的 `ios.entitlements.keychain-access-groups` 只列 **`$(AppIdentifierPrefix)phd.starry.shared`**，避免沿用過時的 `phd.starry.sso`。SDK `sharedStorage` 用 Expo `expo-secure-store` 的 iOS Keychain，固定 `keychainService=starry-sso-v1`、鍵名 `starry.sso`；這套 API 支援 `accessGroup`，為避免在 JS 內寫 Apple Team ID 或錯用未展開的 Xcode 變數，採用**簽章後 entitlement 的第一個預設 Keychain 群組**。其他繁星 iOS App 必須以相同簽章和群組順序、service 及鍵名配合。請在 EAS iOS 簽章包驗證 entitlement 和兩款 App 登入／登出／換人。

**網頁版必做：已在 Clock 補上，尚待真實瀏覽器驗證。** 更新官方 SDK 的 `shareWebSignIn()`、`syncWebSignIn()`、`completeWebSsoCheck()`、`signOutWebEverywhere()`：Apple／Google Relay 或 Passkey 登入後交由 Starry ID 中央 `/auth/sso/adopt` 記住同瀏覽器會員；每次載入以 5 分鐘節流的 `/auth/sso/check` 比對；回來先處理 SSO callback 再處理 OAuth callback；本瀏覽器登出使用 `/auth/sso/logout`。SSO returnUrl 固定 `https://clock.starry.phd/`，是已登記、無 `#` 的合法網址；不用 localStorage 保存跨網域憑證。網頁版只在同一個瀏覽器連動，**不與手機 App 共用登入**。

**Android 跨 App SSO 為選做：不阻擋此 PR 的後續驗收。** Expo SecureStore 是 App 私有儲存，不能偽稱已跨 App 共用。Native Passkey 仍須與 APK 的真正簽章相符。Google Play 安裝版用 Play Console「應用程式簽署」App signing key 憑證 SHA-256；EAS Preview APK 用其實際 EAS 簽章（`eas credentials -p android` 或 APK `apksigner verify --print-certs`），不同時在 Admin Lite 另加一組。
